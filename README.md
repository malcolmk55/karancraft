> **سامانه ثبت فوق‌سریع پرونده‌های بالینی، چند مطبی، شبکه اشتراک پزشکان و دستیار هوشمند بالینی**  
> منطبق با اسناد نیازمندی‌ها و معماری محصول (`doc/01` تا `doc/09`)

## ۱. نمای کلی سیستم و قابلیت‌های پیاده‌سازی‌شده

این سامانه به عنوان یک راه‌حل مدرن، فوق‌سریع و ارگونومیک برای پزشکان ایرانی طراحی شده است تا معضل ثبت طولانی و خسته‌کننده پرونده‌های کاغذی یا نرم‌افزارهای پیچیده سنتی را برطرف کند. تمامی الزامات مستندات پروژه به صورت کامل در کد پیاده‌سازی شده‌اند:

### ۱.۱. ثبت فوق‌سریع بالینی و اسلایس عمودی (اسناد ۰۱، ۰۲، ۰۳)
- **ثبت در کمتر از ۲۵ ثانیه:** دسترسی به الگوهای آماده تشخیصی و شکایات تخصصی بدون نیاز به تایپ انشایی.
- **کرنومتر و تحلیل راندمان (Phase 1.5):** ثبت ثانیه‌ای مدت زمان ویزیت، سنجش درصد استفاده از داده‌های ساختاریافته و تخمین زمان صرفه‌جویی‌شده مطب.
- **تحلیل خودکار علائم حیاتی:** بررسی بلادرنگ فشار خون، ضربان قلب، دما، اشباع اکسیژن ($SpO_2$)، قند خون ($BS$) و محاسبه خودکار شاخص توده بدنی ($BMI$).
- **خروجی چاپی حرفه‌ای نسخه و خلاصه ویزیت:** قالب تمیز بدون المان‌های اضافی پنل جهت پرینت یا ارائه به بیمار.

### ۱.۲. ورود پویای داده و مدیریت خطاهای AI — Escape Hatches (سند ۰۹)
- **اصل «عدم توقف پزشک»:** اگر یافته یا تشخیصی در الگوها نباشد، پزشک هرگز متوقف نمی‌شود.
- **تایپ مستقیم و کلید Enter:** پزشک در کادر جستجوی هر بخش عبارت دلخواه خود را تایپ کرده و با زدن Enter، آن را به عنوان یک کپسول سفارشی (**Custom Chip**) اضافه می‌کند.
- **دیکته صوتی محلی (Contextual Dictation 🎤):** آیکون میکروفون اختصاصی در کنار فیلد شکایت، معاینه و تشخیص جهت دیکته سریع همان بخش.
- **یادداشت افزوده برای الگوها (Item Modifiers):** امکان کلیک روی «+ یادداشت» در هر الگوی انتخابی (مثلاً: `درد اپی‌گاستر` $\rightarrow$ یادداشت: `فقط پس از لبنیات`).
- **مدیریت عدم نگاشت در هوش مصنوعی (AI Unmapped Handling):** نمایش الگوهای استاندارد با برچسب سبز/آبی و نمایش یافته‌های سفارشی یا عبارات ناشناخته صوتی با رنگ **نارنجی (Amber)** بدون دور ریختن هیچ داده‌ای.

### ۱.۳. مدل چند مطبی — Multi-Office (سند ۰۷)
- **عضویت در چند مرکز درمانی:** پزشک می‌تواند مالک یا عضو چندین مطب مستقل باشد (مثلاً مطب ونک، درمانگاه سعادت‌آباد و کلینیک شیراز).
- **سوییچ لحظه‌ای بین مطب‌ها:** منوی کشویی در هدر برای جابه‌جایی آنی میان مطب‌ها یا انتخاب گزینه **«همه مطب‌ها (نمای یکپارچه)»**.
- **برچسب مطب مبدأ:** هر بیمار به مطب ایجادکننده الصاق شده و تفکیک پرونده‌ها حفظ می‌شود.
- **امکان تعریف مطب جدید:** فرم افزودن مطب و درمانگاه در کمترین زمان.

### ۱.۴. شبکه ارتباط پزشکان و اشتراک‌گذاری پرونده (سند ۰۷)
- **جست‌وجوی همکاران:** جست‌وجوی سایر پزشکان بر اساس نام، شماره نظام پزشکی، تخصص و شهر.
- **جریان ارتباط کاری (Connection Workflow):** ارسال درخواست ارتباط، پذیرش، رد یا مسدودسازی.
- **اشتراک پرونده بیمار (Patient Sharing):**
  - حفظ کامل مالکیت پرونده برای پزشک مبدأ.
  - تعیین سطح دسترسی: **فقط‌خواندنی (Read-Only)** جهت مشاوره یا **خواندن و ثبت ویزیت (Read/Write)** جهت ارجاع و درمان تکمیلی.
  - چک‌باکس رعایت محرمانگی و رضایت بیمار (`patientConsent`).
  - یادداشت ارجاع اختصاصی برای همکار و امکان لغو دسترسی در هر لحظه.
  - تب اختصاصی **«بیماران مشترک»** برای مشاهده پرونده‌هایی که همکاران به اشتراک گذاشته‌اند.

### ۱.۵. مدیریت نقش‌ها و کنترل دسترسی — RBAC (سند ۰۶)
- **نقش پزشک (Doctor):** دسترسی کامل به پرونده بیماران خود، ثبت ویزیت، اشتراک پرونده و مدیریت اشتراک.
- **نقش منشی (Receptionist):** پذیرش بیمار، ثبت اطلاعات هویتی و تماس اولیه، جست‌وجوی مراجعین مطب، با **محدودیت دسترسی کامل به تشخیص‌ها، ویزیت‌ها و پرونده‌های محرمانه**.
- **نقش ادمین کل (Admin):** نظارت بر کاربران، ایجاد کاربر، انتساب پزشک و منشی به مطب‌ها، مشاهده آمار کلان و لاگ ممیزی.
- **سوییچ سریع نقش‌ها (Session Selector):** امکان تست آنی هر ۳ نقش در هدر برنامه جهت بررسی تجربه‌ی کاربری.

### ۱.۶. طرح‌های اشتراک، پرداخت دوره‌ای و موتور هوش مصنوعی (سند ۰۸)
- **طرح‌های چهارگانه:**
  - **آزمایشی (Trial):** سقف ۲۰ بیمار، ۱۴ روز رایگان.
  - **برنزی (Bronze):** سقف ۱۰۰ بیمار، ۱ مطب، ۱ منشی، ۵ ارتباط همکار.
  - **نقره‌ای (Silver):** سقف ۵۰۰ بیمار، ۳ مطب، ۳ منشی، ۲۰ ارتباط همکار، آمار پیشرفته.
  - **طلایی هوشمند (Gold + AI):** بیمار و مطب نامحدود، فعال‌سازی دیکته صوتی هوش مصنوعی (AI Voice 🎤).
- **پایش سقف سهمیه (Plan Quota):** نوار پیشرفت مصرف پرونده‌ها و مسدودسازی خودکار ثبت در صورت عبور از سقف مجاز همراه با پیشنهاد ارتقا.
- **شبیه‌سازی پرداخت و صدور فاکتور:** اتصال به درگاه‌های ایرانی (زرین‌پال، آیدی‌پی)، تولید کد رهگیری و تاریخچه فاکتورها.
- **معماری بهینه‌سازی هزینه AI:** استفاده ترکیبی از `Groq Whisper-Large-V3` برای تبدیل بلادرنگ صوت و `DeepSeek-V3` برای استخراج پزشکی بدون اطلاعات هویتی (Zero Data Retention) جهت حذف نیاز به سرورهای گران‌قیمت GPU.

### ۱.۷. امنیت، ممیزی و محافظت کامل در برابر ربات‌ها (اسناد ۰۲ و ۰۵)
- **لاگ ممیزی کامل (Audit Trail):** ثبت تمامی رویدادهای حساس (ایجاد بیمار، نهایی‌سازی ویزیت، اشتراک‌گذاری، ورود و خروج) همراه با متادیتای تغییرات.
- **مسدودسازی کامل ربات‌ها و خزنده‌های وب (Anti-Crawler):** اعمال هدرهای سخت‌گیرانه `X-Robots-Tag: noindex, nofollow, noarchive, nosnippet` در تمامی مسیرها از طریق `vercel.json` و `app/robots.ts` جهت تضمین حریم خصوصی داده‌های سلامت.
- **پشتیبان‌گیری مستقل بدون وابستگی به سرور:** امکان دانلود فایل JSON پشتیبان کامل دیتابیس با نسخه ۲.۰ و بازیابی آن در هر زمان.

## ۲. مراحل استقرار در دو فاز: تست (Vercel) و پروداکشن (هاستینگ لیارا)

همان‌طور که در نیازمندی‌ها ذکر شد، اطلاعات بک‌اند و پایگاه داده در سمت شما قرار ندارد. بر این اساس، فرآیند راه‌اندازی و انتشار به **دو فاز مجزا** تقسیم شده است:

```
┌──────────────────────────────────────────────┐
│  فاز ۱: محیط تست و دمو (Vercel)              │
│  - بدون نیاز به دیتابیس                      │
│  - ذخیره‌سازی سمت کلاینت (LocalStorage v2)    │
│  - شبیه‌سازی API Routes و تست هر ۳ نقش        │
│  - تست سریع توسط پزشکان و سهامداران          │
└──────────────────────┬───────────────────────┘
                       │
                       ▼ خروجی فایل JSON پشتیبان
┌──────────────────────────────────────────────┐
│  فاز ۲: محیط پروداکشن واقعی (هاستینگ لیارا)  │
│  - سرور اختصاصی Node.js Next.js              │
│  - دیتابیس PostgreSQL مدیریت‌شده لیارا       │
│  - اجرای شمای پایگاه داده با Prisma          │
│  - سرور داخل ایران (تطابق با حاکمیت داده)    │
│  - اتصال به درگاه زرین‌پال و APIهای Groq/AI  │
└──────────────────────────────────────────────┘
```

---

### فاز ۱: راهنمای استقرار تست و پیش‌نمایش بر روی Vercel

محیط تست به شما امکان می‌دهد سیستم را با ظاهر چشم‌نواز و عملکرد کامل به پزشکان و داوران نشان دهید، بدون اینکه درگیر هزینه سرور یا پیکربندی دیتابیس شوید.

#### چه امکاناتی در نسخه تست Vercel فعال است؟
- تمامی صفحات، فرم‌ها، پاپ‌آپ‌ها و انیمیشن‌ها.
- قابلیت انتخاب و سوییچ بین هر ۳ نقش (ادمین، پزشک متخصص، منشی).
- سوییچ بین مطب‌ها (ونک، سعادت‌آباد، شیراز) و تعریف مطب جدید.
- سیستم شبکه پزشکان، ارسال درخواست ارتباط و اشتراک پرونده بیمار.
- سیستم اشتراک‌ها، ارتقای آنی طرح (Trial $\rightarrow$ Silver $\rightarrow$ Gold) و اعمال محدودیت سقف بیمار.
- قابلیت ورود پویای داده (Escape Hatches) و دیکته صوتی (Web Speech API).
- پشتیبان‌گیری و بازیابی داده‌ها به صورت فایل JSON.
- بلوکه بودن ۱۰۰٪ خزنده‌ها توسط هدرهای امنیتی Vercel.

#### مراحل استقرار روی Vercel (ظرف کمتر از ۲ دقیقه):

1. **روش اول: اتصال مستقیم گیت‌هاب (پیشنهادی)**
   - کد پروژه را در گیت‌هاب خود Push کنید.
   - وارد سایت [vercel.com](https://vercel.com) شوید.
   - روی دکمه **Add New Project** کلیک کرده و مخزن گیت‌هاب را انتخاب کنید.
   - فریم‌ورک به طور خودکار `Next.js` تشخیص داده می‌شود.
   - بدون نیاز به تعریف متغیر محیطی، دکمه **Deploy** را بزنید.

2. **روش دوم: استفاده از ابزار Vercel CLI**
   ```bash
   pnpm install -g vercel
   vercel login
   vercel
   ```
   برای انتشار نهایی نسخه تست:
   ```bash
   vercel --prod
   ```

#### حساب‌های پیش‌فرض دمو برای تست نقش‌ها در Vercel:
از منوی گوشه بالای هدر برنامه می‌توانید فوراً کاربر فعال را تغییر دهید:
- **دکتر سارا علوی:** متخصص داخلی (دسترسی به مطب ونک و سعادت‌آباد، مدیریت بیماران و شبکه)
- **دکتر احسان رضایی:** پزشک عمومی درمانگاه سلامت (امکان دریافت پرونده مشترک و ثبت ویزیت)
- **مریم فراهانی (منشی):** منشی مطب ونک (فقط ثبت پذیرش و اطلاعات هویتی)
- **مهندس حسینی (ادمین):** مدیر سیستم (مشاهده کاربران، لاگ ممیزی و داشبورد کلان)

### فاز ۲: راهنمای استقرار محیط عملیاتی (Production) بر روی هاستینگ ابری لیارا (Liara)

هنگامی که آماده راه‌اندازی سامانه در فضای واقعی برای مطب‌ها و کلینیک‌های کشور شدید، پلتفرم ابری **لیارا** به دلیل استقرار سرورها در دیتاسنترهای داخلی، پشتیبان‌گیری خودکار روزانه، عدم نیاز به مدیریت سرور لینوکس (PaaS) و هزینه ریالی، انتخاب استاندارد است.

#### مراحل گام‌به‌گام راه‌اندازی در لیارا:

#### گام ۱: ساخت برنامه و پایگاه داده در کنسول لیارا
1. وارد حساب کاربری خود در [کنسول لیارا](https://console.liara.ir) شوید.
2. از منوی **برنامه‌ها** $\rightarrow$ **ایجاد برنامه جدید**:
   - پلتفرم: **NodeJS**
   - شناسه برنامه: مثلاً `medidoc-app`
   - پلن سخت‌افزاری پیشنهادی: حداقل ۲ هسته CPU و ۲ گیگابایت رم
3. از منوی **دیتابیس‌ها** $\rightarrow$ **ایجاد دیتابیس جدید**:
   - نوع دیتابیس: **PostgreSQL** (نسخه ۱۵ یا ۱۶)
   - شناسه دیتابیس: مثلاً `medidoc-db`
   - پس از ساخت، مقدار **URI اتصال به دیتابیس** (شامل یوزرنیم، پسورد، پورت و هاست) را کپی کنید.

#### گام ۲: تنظیم متغیرهای محیطی در پنل لیارا
وارد برنامه `medidoc-app` در لیارا شده و از بخش **تنظیمات** $\rightarrow$ **متغیرهای محیطی**، مقادیر زیر را (مطابق با فایل `.env.example`) اضافه فرمایید:

```ini
NODE_ENV=production
NEXT_PUBLIC_APP_URL=https://medidoc.ir
NEXTAUTH_URL=https://medidoc.ir
NEXTAUTH_SECRET=یک_رشته_تصادفی_۳۲_کاراکتری_بسیار_امن
DATABASE_URL=postgresql://db_user:db_pass@db_host:5432/db_name?sslmode=disable
HEALTH_DATA_ENCRYPTION_KEY=یک_کلید_۳۲_کاراکتری_جهت_رمزنگاری_داده_سلامت

# هوش مصنوعی (اختیاری جهت فعال‌سازی AI واقعی)
GROQ_API_KEY=gsk_...
DEEPSEEK_API_KEY=sk_...

# درگاه بانکی
ZARINPAL_MERCHANT_ID=کد_مرچنت_زرین‌پال
```

#### گام ۳: راه‌اندازی دیتابیس با Prisma
فایل شمای کامل PostgreSQL در مسیر `prisma/schema.prisma` آماده است. برای اعمال جداول روی دیتابیس لیارا:
```bash
# تنظیم آدرس دیتابیس لیارا در سیستم محلی موقت یا از طریق CLI لیارا
export DATABASE_URL="postgresql://db_user:db_pass@db_host:5432/db_name?sslmode=disable"

# ساخت تمام جداول روی PostgreSQL لیارا
pnpm prisma db push
```

#### گام ۴: انتشار با Liara CLI
پروژه مجهز به فایل `liara.json` است. کافی است دستور زیر را در پوشه پروژه اجرا کنید:
```bash
# نصب ابزار لیارا در صورت عدم وجود
npm install -g @liara/cli

# ورود به حساب لیارا
liara login

# استقرار اپلیکیشن
liara deploy
```

#### گام ۵: انتقال داده‌های آزمایشی به دیتابیس پروداکشن
- در محیط تست ورسل وارد بخش **«پشتیبان‌گیری»** شده و دکمه **«دانلود فایل پشتیبان (JSON)»** را بزنید.
- این فایل شامل تمام الگوهای تخصصی، نمونه بیماران، مطب‌ها و طرح‌های اشتراک است که می‌توانید از طریق پنل ادمین پروداکشن یا اسکریپت Seed در دیتابیس واقعی بارگذاری کنید.

#### گام ۶: اتصال دامنه اختصاصی و گواهی SSL
- در کنسول لیارا وارد بخش **دامنه‌ها** شوید.
- دامنه مطب خود (مثلاً `medidoc.ir` یا زیردامنه `app.yourclinic.ir`) را وارد کنید.
- رکوردهای CNAME و TXT ارائه‌شده را در پنل کلودفلر یا ارائه‌دهنده DNS ثبت کنید.
- گواهی امنیتی رایگان Let's Encrypt به صورت خودکار ظرف چند دقیقه فعال خواهد شد.

#### گام ۷: پیکربندی پشتیبان‌گیری خودکار
- از پنل دیتابیس PostgreSQL لیارا، تب **پشتیبان‌گیری** را باز کنید.
- پشتیبان‌گیری خودکار روزانه فعال است و فایل‌های دامپ رمزنگاری‌شده در فضای ذخیره‌سازی ابری امن نگهداری می‌شوند.

## ۳. معماری فایل‌ها و پشته فنی

```
MediDoc/
├── app/
│   ├── api/                     # اندپوینت‌های API
│   │   ├── patients/            # دریافت و جستجوی بیماران
│   │   ├── visits/              # ویزیت‌ها
│   │   ├── templates/           # الگوهای آماده
│   │   └── v1/                  # معماری استاندارد API نسخه ۱ (سند ۰۵)
│   │       ├── auth/me          # اطلاعات کاربر لاگین‌شده
│   │       ├── patients/        # CRUD بیماران با تفکیک مطب
│   │       ├── visits/          # ذخیره و نهایی‌سازی ویزیت
│   │       ├── doctors/         # شبکه پزشکان و اتصالات
│   │       ├── subscriptions/   # طرح‌های اشتراک و فاکتورها
```

## ۴. راهنمای اجرای محلی (Local Development)

### پیش‌نیازها:
- Node.js نسخه ۲۰ یا بالاتر
- مدیر بسته‌ی `pnpm` (یا npm / yarn)

### راه‌اندازی:
```bash
# ۱. کلون پروژه یا ورود به پوشه
cd /path/to/MediDoc

# ۲. نصب وابستگی‌ها
pnpm install

# ۳. اجرای سرور توسعه محلی
pnpm dev
```
مرورگر را باز کرده و به آدرس [http://localhost:3000](http://localhost:3000) بروید.

### ساخت بسته تولید و بررسی صحت کدها:
```bash
pnpm build
```
